Memory System - how turns remember

One shared token window serves history + RAG + memory. Each turn the decider builds a MemoryEvidence triple, recall pulls two stores, the budget carves and fits everything, and a background worker rolls older turns into episodic rows. RAG answers from uploaded files; memory supplies the personal side of the same window. Source of truth: docs/memory-system.md (temp HTML companion).

1 Budget first - everything keys off it context_budget.py · config.py

One window, carved in order. EFFECTIVE_N_CTX is 4096 below 12 GB RAM, 8192 at or above, or LLAMA_N_CTX override. Nothing takes a fixed token constant outside allocate.

  1. total = window − 256 safety margin, always held back
  2. answer reserve: 512 at 4K · 768 at 8K
  3. usable = total − answer − system − query
  4. memory carve first: 300 at 4K / 500 at 8K when needs_memory, else 0
  5. route split on the rest: RAG → rag_cap = rest × share · DIRECT → history takes its share, rag_cap = 0

3 Dynamic split - one mem_cap, two stores rag_graph.py

Gate is cheap on purpose. MemoryEvidence(needs_memory, sem_hit, epi_hit) = Laya ≥ 0.8 OR keyword/history/semantic-key stub hit OR episodic token overlap over recent 10. No vector is computed at gate time.

The winner fits first up to 70%, the other takes the remainder. Same evidence drives allocate(needs_memory=…), so strong evidence keeps its carve before RAG and history are fitted.

4 Lifecycle - rollup then compact background · fail-open

Request path never summarizes. After the reply is saved, RollupJob.submit enqueues one tuple and returns in microseconds - no model touch. One daemon worker reloads history (limit 100), runs rollup, then compaction.

  • Merge protections: create-first then delete parents (failure keeps both); new row keeps min start / max end, oldest created_at, max recall stats.
  • Forget protections: only when still over cap, up to over-cap count; just-merged row excluded from same-pass forget.
  • Every failure fails open → next turn truncates oldest instead. Nothing on this path can break a chat turn.

7 Failure modes + test map fail-open everywhere

No engine / no tokenizerTurn still works: ceil(len/4) estimate, truncate-oldest instead of rollup.
Gate / retrieval errorDIRECT with plain messages; RAG with zero hits reroutes to DIRECT; Laya/grade/rewrite fall back to SLM path, fused order, advisory grades, original query.
Memory errorOverlap-only recall, semantic-only text, or no memory block. A memory-less turn never touches the embed engine; shape mismatch → overlap-only.
Rollup / compact errorBusy engine, timeout, empty summary → None. Merge abort keeps both parents. Forget/touch errors log at debug and keep rows.
Topic / migration errorSibling failure → empty lines, prompt unchanged. Schema backfill is idempotent and never raises; fresh DB is a no-op.
Teststest_episodic: trigger, ranking, merge/forget · test_rag: budget, topic, message build · test_migrate: backfill · test_laya: gates · test_rag_eval / test_worker: quality + engine
